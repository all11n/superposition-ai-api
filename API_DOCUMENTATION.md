# API игры «Суперпозиция» — контракт интеграции

## Назначение

API принимает текущее состояние игры и возвращает один полный ход ИИ, состоящий из двух разыгрываемых карт.
Сейчас доступны три уровня:
- `low` — быстрая эвристика
- `mcts` — MCTS с ограничением времени до 4.5 секунд на ответ
- `high` — нейросетевая MLP

Все три уровня используют один игровой движок и одну таблицу переходов карт

---

## 1. Основной endpoint

### `POST /choose-action`

Используется приложением для получения хода ИИ

### Входной JSON

```json
{
  "model": "mcts",
  "board": [4, 2, 5, 0, 0, 3, 0, 4],
  "targets": [
    [3, 0, 4, 5],
    [5, 3, 0, 2]
  ],
  "hands": {
    "ai": ["Y", "Z3", "RX", "IDENTITY"],
    "opponent": ["X", "S_DAG", "BARRIER", "RESHUFFLE"]
  },
  "deck": [],
  "discard": [],
  "move_number": 0,
  "max_moves": 80,
  "protected": [
    [false, false, false, false],
    [false, false, false, false]
  ],
  "time_limit": 4.5
}
```

### Обязательные поля

#### `model`

Тип: `string`

Допустимые значения:

```text
low
mcts
high
```

#### `board`

Тип: `integer[8]`
Текущее состояние 8 кубитов
Каждый элемент должен быть целым числом от `0` до `5`
В мобильной постановке:

```text
board[0..3] = кубиты ИИ
board[4..7] = кубиты соперника
```

#### `targets`

Тип: `integer[2][4]`

Целевые состояния двух сторон

```text
targets[0] = цель ИИ
targets[1] = цель соперника
```

Каждое значение от `0` до `5`.

**Важно:** если разработчики хотят передавать только `board + карты`, необходимо отдельно договориться, откуда сервер получает `targets`. Без целевого состояния модель не может корректно определить, какие кубиты являются правильными и какой ход благоприятен. В текущем API `targets` является обязательным полем.

#### `hands.ai`

Тип: `string[]`
Карты, которые сейчас находятся на руках ИИ.
Количество карт может быть произвольным, но для существующего правила полного хода должно быть не менее двух допустимых карт.
Названия должны совпадать с идентификаторами карт в `CARD_DB`

---

## 2. Поля, которые желательно передавать

### `hands.opponent`

Тип: `string[]`

Карты соперника
Для `low` и `high` это не обязательно концептуально, но для `mcts` желательно/необходимо, тк MCTS должен иметь информацию о возможных ответах соперника
В текущей реализации для `mcts` требуется минимум две карты соперника

### `deck`

Тип: `string[]`

Оставшаяся колода
Если приложение пока не готово её передавать, можно отправлять `[]`. Для полноценного моделирования будущих ходов MCTS лучше передавать реальное состояние колоды

### `discard`

Тип: `string[]`
Карты в сбросе

### `protected`

Тип: `boolean[2][4]`
Состояние защищённых/измеренных кубитов, если эта механика используется приложением

### `move_number`

Тип: `integer`.
Номер текущего хода

### `max_moves`

Тип: `integer`
Максимальное число ходов при симуляции

### `time_limit`

Тип: `number`
Используется для MCTS. Максимум текущего API — `4.5` секунды
Если поле не передано, используется `4.5` секунды

## 3. Ответ API

Ответ содержит выбранный полный ход:

```json
{
  "model": "mcts",
  "action": {
    "first": {
      "card_id": "Z3",
      "targets": [0, 1, 2]
    },
    "second": {
      "card_id": "Y",
      "targets": [6]
    }
  },
  "thinking_time_ms": 4502.1,
  "ai_correct_before": 0,
  "opponent_correct_before": 2,
  "favorability": 1,
  "iterations": 3796
}
```

Для игровой интеграции главное поле:

```text
action
```
Остальные поля являются диагностическими и могут игнорироваться приложением

---

## 4. Что означает `action`

`action` — весь ход ИИ

В каждом ходе две части:

```text
first  = первая карта + её цели
second = вторая карта + её цели
```

Например:

```json
{
  "first": {
    "card_id": "Z3",
    "targets": [0, 1, 2]
  },
  "second": {
    "card_id": "Y",
    "targets": [6]
  }
}
```

означает:

1. сыграть `Z3` на кубиты `0, 1, 2`;
2. сыграть `Y` на кубит `6`.

Приложение после получения ответа само применяет эти карты к своему игровому состоянию

---

## 5. `favorability`

favorability - диагностическая метрика из текущей модели
Она рассчитывается как изменение количества правильных состояний:
```text
изменение правильных кубитов ИИ − изменение правильных кубитов соперника
```

Положительное значение означает, что непосредственный результат хода благоприятен для ИИ, это поле не требуется для работы приложения

## 6. GET endpoints

### `GET /health`

Проверка доступности сервера

Пример:

```json
{
  "status": "ok",
  "neural_model": "loaded",
  "models": ["low", "mcts", "high"]
}
```

### `GET /models`

Возвращает доступные уровни ИИ и их описание

## 7. Логика взаимодействия приложения с API

```text
ИГРА
  │
  │ 1. Наступил ход ИИ
  │
  │ 2. Игра формирует JSON
  │
  ▼
POST /choose-action
  │
  │ board + targets + cards + model
  ▼
FASTAPI
  │
  ├── low  → эвристика
  ├── mcts → MCTS
  └── high → нейросеть
  │
  ▼
JSON с двумя картами
  │
  ▼
ИГРА
  │
  ├── применяет первую карту
  └── применяет вторую карту
```

## 8. Минимальный рекомендуемый контракт для мобильного приложения
для основной интеграции достаточно:

- выбранный уровень;
- текущее состояние кубитов;
- цели;
- карты ИИ;
- карты соперника для MCTS

Колода, сброс и дополнительные поля можно подключить позже.
```json
{
  "model": "mcts",
  "board": [4, 2, 5, 0, 0, 3, 0, 4],
  "targets": [
    [3, 0, 4, 5],
    [5, 3, 0, 2]
  ],
  "hands": {
    "ai": ["Y", "Z3", "RX", "IDENTITY"],
    "opponent": ["X", "S_DAG", "BARRIER", "RESHUFFLE"]
  }
}
```

## 9. Важное ограничение прототипа

Сейчас API работает с мобильной конфигурацией:

```text
8 кубитов = 4 ИИ + 4 соперника
```

Кроме того, таблица переходов `GATE_TRANSITIONS` в текущем прототипе является тестовой
Также список `CARD_DB` должен быть синхронизирован с реальными картами мобильной игры
